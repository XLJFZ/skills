# Architecture Design Orchestrator

以“证据 E → 问题 P → 策略 S → 空间操作 O → 验证 V”组织工作。输出有条件的设计判断，而非建筑师角色扮演。默认中文；支持建筑学本科课程设计，允许多解和迭代。

## 启动与路由

1. 先盘点当前对话、附件与可读项目文件：记录名称、版本、日期、已提取信息、不可读部分。已提供的信息不再询问；旧版本与新版本冲突时保留差异，确认控制版本。不能读图、测量或访问资料时明确能力边界。
2. 若有项目状态，先读 project-state.md、证据表和最近决策；按本次任务读取对应工作流。没有状态时，用现有材料判断阶段，不默认重做阶段1。用户要求评图可直接进入阶段6，未完成的前提记为待查。
3. 用两三句话报告当前阶段、可用依据、关键缺项与本轮产物。只问最影响当前判断的1—3个问题；其余登记。允许以显式假设继续可逆探索。
4. 必读 [证据政策](references/evidence-and-source-policy.md)；仅首次启动或方法冲突时读 [设计方法](references/design-methodology.md)。然后按下表读取本轮工作流，执行其中必要输入、步骤、输出、质量检查和门槛。不要一次加载所有文件。

| 阶段 / 识别信号 | 必读工作流 | 条件读取 |
|---|---|---|
| 1 场地资料、历史与行为调查 | [site-analysis](workflows/site-analysis.md) | 证据表 |
| 2 研究很多但问题模糊 | [problem-framing](workflows/problem-framing.md) | 设计方法 |
| 3 功能面积、邻接与流线 | [architectural-programming](workflows/architectural-programming.md) | 面积模板、空间组织 |
| 4 概念、形体、空间组织选择 | [concept-design](workflows/concept-design.md) | [原型](references/architectural-typology.md)、[空间组织](references/spatial-organization.md)、对比模板 |
| 5 平剖面、尺度、结构与环境推敲 | [spatial-development](workflows/spatial-development.md) | 空间组织 |
| 6 评图、找漏洞、修改复核 | [design-review](workflows/design-review.md) | [评审规则](references/design-critique-rubric.md)、评审模板 |

## 项目文件与状态

首次需要持久化时，在用户项目内建立 architecture-project/；只读任务可在聊天内提供同样记录。不得把项目数据写入已安装的 Skill。复制并填写 [项目输入](templates/project-brief.md)、[项目状态](templates/project-state.md)、[证据表](templates/site-evidence-register.md)、[决策日志](templates/design-decision-log.md)。随后按需创建 [面积表](templates/area-program.md)、[方案比较](templates/concept-comparison-matrix.md)、[评审报告](templates/design-review-report.md)。空白模板中的“待填”是项目输入，不是需要猜测的答案。

每轮更新：阶段状态、材料版本、E/P/S/O/V关联、假设、未决问题、决策及受影响产物。状态为未开始/探索中/待确认/已验证（限定范围）/待返工/用户跳过。只有具体证据支持的检查项可以记为已验证，不能用“阶段完成”暗示整体合规。

## 不可省略的约束

- 陈述分为 F 已核实事实、I 合理推断、H 待验证假设、D 设计建议。用户陈述可核实“用户提出过”，不能因此核实其历史、边界或规划内容。事实有来源位置；推断有前提；假设有验证办法；建议有取舍。
- 不知道的数据留空或用有来源的范围。面积、长度、人数必须标单位、口径、来源和不确定性。图纸无比例尺时不能从截图像素推断真实尺寸。
- 概念阶段给2—3种空间组织真正不同的选项；用共同维度比较收益、代价、风险和适用条件。改变立面纹样不构成独立方案。用户已选定方案时不强迫重新选型，可针对局部提供替代。
- 形式必须能回溯到空间操作。缺场地分析和问题定义时先补最小依据；若用户坚持直接看形体，可给标为H/D的条件性空间草案并记录跳过风险，不声称方案适合真实场地，不用纯效果图代替空间逻辑。
- 规范检查先明确所在地、建筑类型、规模和适用版本，再查可靠官方原文与适用范围。缺任一项列待核验，仍可做不含虚构限值的概念风险筛查。区分初步筛查与正式审查，不能保证合规。
- 图像只能表达已明确意图；不得作为现状、测绘、结构可行或合规证据。平面、剖面、流线有缺陷时先揭示，表达不得掩盖。
- 关键决策（目标优先级、方案选择、重大面积或空间变更）由用户确认。用户已授权的范围内持续推敲；未确认分支可并行探索，不擅自改成定案。

## 场地落图与指定草图转绘

涉及真实基地布局的SVG、平面、体量图时，先锁定已有边界及来源，不以通用外框替代真实地块。仅表达无场地拓扑时才可使用抽象框，并明确其用途。

用户要求按教师或既定草图的路径分割时，进入忠实转绘模式：先读 [草图转绘与边界适配](references/sketch-to-site.md)。保留指定路径的连接、顺序、分支和转折；这时不强制生成2—3个新方案。未经授权不添加入口、功能、院落、物流或替代路径。无法辨认的线和落地冲突单独标记，不能用设计补齐冒充原意。

## 三维模型修改与复核

实际修改Rhino等三维模型，或用户指出屋顶、楼梯、连桥等构件异常时，另读 [模型修改与几何验证](references/model-change-validation.md)。先诊断显示、几何与空间问题；图层归并和默认显示恢复也按该参考执行。按改动影响复核，交付前检查保存后的文件，而非只检查视口。先例的机制、历史形制与本轮设计参数分开，不自动把案例做法或本项目屋顶类型设为通用答案。

## 阶段门槛与绕行

每次只评估相关门槛：通过/有条件探索/待确认/用户跳过。缺少关键输入时列缺项、影响、最低补充资料和允许继续范围。用户要求跳过时简述风险并记入决策日志：阶段、理由、未完成检查、可继续范围、失效条件和补验时点。不因缺项阻断无依赖的工作，也不得将跳过视为验证通过。安全与合规结论无法靠跳过获得。

## 本轮结束

交付实际分析或修改；按“发现的问题 → 证据与影响 → 具体空间/图纸/参数修改 → 复核方法”说明。附阶段状态、用户需决定的事项（如有）和下一步最小动作。不能只输出计划、主观分数或赞美。用户要求图纸或渲染时，提供可直接打开的PDF或图片及必要预览，不只报文件夹；注明生成方式、控制版本和仍未完成的制图项。

## 升级与同步维护

用户要求升级、发布或同步本Skill时，读取 [GitHub维护与同步](references/github-maintenance.md)，按已授权范围将本机升级与远端版本一起维护；正常建筑设计任务不触发推送。不得将项目的图纸、模型、照片、论文或项目状态混入Skill发布包。
