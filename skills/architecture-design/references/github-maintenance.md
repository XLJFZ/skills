# GitHub维护与同步

## 维护目标

- 仓库：https://github.com/XLJFZ/skills
- 分支：main
- Skill目录：skills/architecture-design
- 本机安装目录：CODEX_HOME/skills/architecture-design（未设置时使用用户目录的.codex/skills/architecture-design）。

当用户要求继续升级本Skill，并已有同步升级授权时，升级任务包含将验证后的版本同步到以上目录；普通项目建模或设计不触发发布。更换目标、公开额外资料或覆盖不明远端修改不在这一范围内。

## 每轮升级

1. 先比较本机与远端版本、文件及当前分支头。发现远端更新时先读差异并合并，不静默用旧快照覆盖。保留其他Skill及仓库文件。
2. 按实际变更更新SKILL.md版本、CHANGELOG.md及相应参考/回归案例。项目失败可抽象为通用规则，不将个人项目细节或文件混入包中。
3. 检查相对引用、版本、文件清单和内容。运行可用验证器；缺依赖就说明实际执行的替代检查，不将未跑的行为测试写成通过。
4. 发布一个可追溯提交，明确目标为本Skill目录。优先使用可用GitHub连接器批量建树和提交，或已有认证的Git工具；不另索要明文令牌。更新分支时带期望旧SHA且不强推，避免覆盖并发提交。
5. 回读远端分支和目录，比对提交及文件哈希。只有远端确认成功才报告已同步。若失败，保留本机版本与待发差异，明确未完成，不能声称未来会自行后台重试。

## 同步方向

默认本机有意修改 → 验证 → GitHub，并检查远端冲突；需要从GitHub更新其他设备时，读取目标目录并比较，备份后更新本机。同步是每次升级任务的一部分，不是定时任务、常驻文件监听或后台服务。

## 发布边界

仅Skill通用文件：SKILL.md、agents、references、workflows、templates、tests、明确标注的示范案例及安装/版本说明。不要上传architecture-project/、sources/、真实项目模型/图片/课件、凭据、缓存、本机绝对路径及项目材料清单。
